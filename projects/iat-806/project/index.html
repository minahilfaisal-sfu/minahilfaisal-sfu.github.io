Final Project — explainer

A drop-in AI assistant that explains any web page, built as an npm library.

Try it now: click the round chat icon in the bottom-right corner. The assistant runs on every page of this site, including this one. Ask it what this page is about, or flip the Sage switch for a spookier guide.

What it does

A website adds one script and a short description of itself, and a chat bubble appears on every page. Visitors can ask about whatever they're looking at. The assistant reads the page, answers in plain language, outlines the parts of the page it's talking about, and suggests follow-up questions. The conversation follows you from page to page.

  • Reads headings, text, lists, tables and image descriptions; skips menus, footers and forms.
  • Highlights the exact paragraph or heading an answer comes from.
  • Suggested follow-up questions, plus a text box for your own.
  • Sage persona: the same facts, with an ominous omen and a darker theme.
  • Keeps the AI key secret through a small proxy, and checks every reply before showing it.

Why

Complex pages and dashboards can overwhelm people without a technical background. My research question is whether explanations that point at what's on the page help non-experts understand it, and whether a playful persona changes engagement or trust. This library is also the first building block of the AI assistant for my thesis project, a dashboard for comparing building-integrated agriculture scenarios.

How I built it

I started from a public template: Lokalise's open-source shared-ts-libs repository, a monorepo for publishing TypeScript libraries to npm. It came with the build, testing, linting and release setup (pnpm, Turborepo, Vite, Vitest, Biome and Changesets), so I could focus on the library itself. I kept its tooling and conventions for a standalone package, whose source lives in this site's repository under projects/iat-806/project/explainer/.

  1. Read the page: walk the main content and tag each readable block (b0, b1, …).
  2. Build the prompt: rules, the site's description, the page data (marked as untrusted) and the recent chat.
  3. Ask the model: through a proxy to a free model on OpenRouter.
  4. Check the reply: drop highlights for blocks that don't exist and links the site didn't list.
  5. Show it: answer, highlights and chips, in a widget isolated with Shadow DOM so the site's styles can't break it.

It's written in TypeScript and builds two ways: a single file for a plain <script> tag (what this site uses), and an npm package with types for React, Vue or any bundled app. It has 31 unit tests and was checked in a real browser.

The project began as Rootbound, a dungeon-master style game where an AI dragon named Sage guided players. I narrowed it to this library to fit the term, and Sage lives on as the persona.

How to use it

On a plain HTML site, add the file and a config on every page:

<script src="explainer.iife.js"></script>
<script>
  Explainer.init({
    endpoint: "https://your-proxy.workers.dev",
    position: "bottom-right",
    site: {
      name: "My Site",
      description: "What this site is for.",
      pages: { "/about.html": "About the project" },
    },
  });
</script>

In an app with a bundler:

import { init } from "@minahilfaisal-sfu/explainer";

init({ endpoint: "https://your-proxy.workers.dev", site: { name: "My App" } });

Mark sections with data-explainer-context="…" to give the assistant hints, or data-explainer-ignore to keep them private.
